# 割り勘計算Webアプリ

グループ旅行や飲み会など、複数人で費用を分担する場面で使える割り勘計算Webアプリ。
各メンバーの立て替え金額と用途を入力すると、最終的な過不足（残高）を計算し、
支払い回数が最小になる精算方法（誰が誰にいくら払うか）を自動で提示します。
バックエンド不要・ビルド不要。ブラウザだけで完結し、オフラインでも動作します。

**公開URL:** https://yukiyoshida022.github.io/warikan-app/

## 主な機能

- **メンバー管理** — 参加者を名前で登録・削除（2人以上）
- **支出入力** — 支払者・金額・用途・割り勘対象者を記録。対象未選択なら全員で割る
- **残高計算** — 各メンバーの過不足（立て替え総額 − 負担総額）を即時再計算
- **精算出力** — 最小送金回数で「誰が誰にいくら払うか」を提示
- **リセット** — 全データを初期化（確認ダイアログあり）

## 使い方

1. **メンバー追加** — 参加者の名前を入力して「追加」（Enterでも可）
2. **支出入力** — 支払者・金額・用途を入れ、割り勘対象者を選んで「支払いを追加」（対象未選択なら全員）
3. **精算計算** — 「精算を計算する」を押すと「誰が誰にいくら払うか」を最小回数で表示

金額は3桁ごとにカンマ区切り + 末尾「円」で表示します（例: `1,200円`）。
残高の符号は受け取り `+1,200円` / 支払い `-800円` / ゼロ `±0円` の形式です。

## ローカルで開く

ビルド不要。`index.html` をブラウザで直接開くだけで動作します。

```
open index.html
```

Playwright 等のツールから開く場合は `file:` が使えないため、ローカルの静的サーバー経由で開きます。

```
python3 -m http.server 8777
# ブラウザで http://localhost:8777/index.html を開く
```

## テストの実行

ロジック（残高計算・精算・端数処理）はプロパティベーステストで検証しています。
テストランナーは Node.js 標準の `node:test`、プロパティ生成に `fast-check` を使用します。

```
npm install      # 初回のみ（fast-check を取得）
node --test      # tests/ 配下のテストを実行
```

JavaScript ファイルの構文は、保存時に Hook が `node --check` で自動チェックします。手動で確認する場合:

```
node --check app.js
```

# Kiro の機能をどこで使ったか

Kiro University Challenge のレッスン順にまとめます。各機能を、このアプリの開発のどこで・どう使ったかを示します。

## 1. Spec（仕様駆動）

`.kiro/specs/warikan-calculator/` に requirements / design / tasks を作成。
`requirements.md` では EARS 形式の受け入れ基準で、メンバー管理・支出入力・残高計算・最小送金回数の精算・リセット・クライアントサイド完結を定義。
用語集（Member / Payment / Balance / Settlement など）で言葉を固定し、以降の実装・テストの土台にしました。

## 2. Steering（プロジェクト共通コンテキスト）

`.kiro/steering/` に 3 ファイルを作成し、常時コンテキストに読み込ませました。

- `product.md` — 何を作るか・主な機能・設計方針・利用シーン
- `tech.md` — バニラ HTML/CSS/JS、ビルド不要、JSDoc 型注釈、`AppState` 単一状態などの技術方針
- `structure.md` — ディレクトリ構成、`app.js` の内部構成、命名規約。
  金額表示ルール（カンマ区切り + 「円」、符号 `+/-/±0`）もここで統一

## 3. Hooks（保存時の自動化）

`.kiro/hooks/js-syntax-check.json` を作成。
`.js` ファイルを保存するたびに `node --check` が走り、構文エラーを即座に検出します（`✅ 構文OK` / `❌ 構文エラー` を表示）。
ESLint 等を入れずに、Node.js 標準機能だけで保存時チェックを実現しました。

## 4. プロパティベーステスト

`tests/property.test.js` で、`node:test` + `fast-check` によるプロパティベーステストを実装。
「どんな入力でも成り立つ性質」を検証しています。例:

- 全メンバーの残高の合計は常に 0（端数が出ても崩れない）
- 対象者未指定は「全員対象」と等価
- メンバー削除時に関連する支払いも必ず消える
- リセット後は必ず空の初期状態になる

`node --test` で 10 件のプロパティが全てパスします。

## 5. Powers（インストール済み Power の活用）

`Context7` Power を使い、HTML 入力欄の最新ドキュメント（MDN）を参照しました。
スマホで金額入力欄に数字キーボードを出すために `inputmode` 属性を調べ、
`<input type="number" inputmode="numeric">` を採用。学習データに頼らず、現在のドキュメントで裏取りしました。

## 6. MCP（外部ツール連携）

`.kiro/settings/mcp.json` に Playwright MCP サーバーを設定。
実ブラウザでアプリを操作し、メンバー登録 → 立て替え入力 → 精算計算までを自動で動かして、
残高・精算結果の表示を実際の画面で確認しました（`file:` が使えないため静的サーバー経由）。

## 7. カスタムエージェント

`.kiro/agents/warikan-verifier.md` に検証専用エージェントを作成。
コード修正のたびに、ブラウザで立て替えを入力して精算結果の正しさと、
金額表示が Steering のルールどおりかをまとめて確認します。
ツールは `read` / `shell` / Playwright のみを許可し、修正はせず検証に専念させています。
